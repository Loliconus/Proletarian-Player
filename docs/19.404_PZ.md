Разработчик: **RedSynthesis**

---

## 1. Введение

Proletarian Player разработан как локальный видеоплеер‑расширение для Chromium‑браузеров.

Ключевая идея: локальные файлы должны воспроизводиться **без аккаунтов, без облака, без сервера**, при минимальном уровне доверия к приложению.

---

## 2. Назначение и область применения

Назначение:

- воспроизведение локальных видеофайлов;
- управление просмотром (очередь, скорость, громкость, режимы отображения);
- субтитры и их синхронизация;
- локальное сохранение прогресса (SmartResume).

Область применения:

- обучение, самообразование, просмотр архивов;
- демонстрация материалов офлайн.

---

## 3. Технические характеристики и обоснование решений

### 3.1. Постановка задачи

Создать плеер‑расширение (MV3), не требующее:

- аккаунта;
- сервера;
- сетевых функций;
- избыточных разрешений браузера.

### 3.2. Главные допущения

- Декодирование выполняет браузер (HTML5 Video). Следовательно, поддержка форматов не “встроена в проект”, а определяется браузером и платформой.
- Доступ к файлам предоставляется пользователем вручную: через диалоги выбора или перетаскивание.
- Прогресс и настройки хранятся локально.

### 3.3. Архитектурные решения

**Почему расширение и вкладка, а не отдельное приложение?**  
Потому что браузер уже содержит медиа‑движок и UI‑платформу (HTML/CSS/JS). Это снижает сложность и не требует отдельного установщика.

**Почему минимальные permissions?**  
В проекте используется только `storage` — для локального хранения прогресса и настроек. Отказ от “лишних” разрешений снижает риск неправильного доступа к данным пользователя.

**Почему popup открывает новую вкладку, а не ищет существующую?**  
Поиск вкладки требует разрешения `tabs`, которое потенциально раскрывает URL и структуру вкладок пользователя. Проект сознательно избегает этого, выбирая более простую модель: открывать вкладку плеера по команде.

### 3.4. Данные и хранение

Используемые хранилища:

- IndexedDB — история просмотра (SmartResume);
- localStorage — пользовательские настройки интерфейса;
- chrome.storage.local — запись “последний просмотр” для popup.

Идентификация файла для истории выполняется по имени и размеру (компромисс между простотой и стабильностью без хеширования содержимого).

### 3.5. Субтитры и совместимость

Браузеры обычно принимают субтитры как WebVTT, поэтому:

- VTT используется напрямую;
- SRT и ASS/SSA конвертируются в VTT;
- синхронизация реализована как сдвиг временных меток VTT.

### 3.6. Очередь и сортировка

Очередь сортируется по результатам разбора имени файла (серии/эпизоды/паттерны), что помогает при просмотре сериалов, курсов и архивов.

---

## 4. Ожидаемые технико-экономические показатели

- Снижение времени на восстановление позиции просмотра (SmartResume).
- Снижение когнитивной нагрузки (единая схема управления).
- Нулевая стоимость эксплуатации сервера (сервер отсутствует).

---

## 5. Источники, использованные при разработке

- стандарты ЕСПД (ГОСТ 19.*) — как ориентир структуры документации;
- документация Chrome Extensions (Manifest V3);
- описание HTML5 Video и поведения `<video>`;
- материалы по File System Access API (диалоги выбора файлов/папок);
- справочные материалы Chromium‑браузеров по расширениям и их разрешениям.
