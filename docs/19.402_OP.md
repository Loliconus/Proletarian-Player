## 1. Общие сведения

Наименование: **Proletarian Player**.  
Форма поставки: расширение Chromium (Manifest V3).  
Языки реализации: JavaScript, HTML, CSS.  
Режим работы: локальный (без серверной части проекта).

---

## 2. Функциональное назначение

Класс задач:

- локальное воспроизведение видеоматериалов;
- управление очередью и параметрами воспроизведения;
- субтитры и синхронизация (сдвиг);
- сохранение прогресса просмотра (SmartResume).

Ограничения:

- декодирование выполняет браузер (HTML5 Video), поэтому поддержка контейнеров/кодеков зависит от платформы;
- открытие папки через системный диалог зависит от File System Access API;
- расширение не открывает “последний файл автоматически”, т.к. доступ к локальным файлам предоставляется пользователем вручную.

---

## 3. Описание логической структуры

### 3.1. Структура модулей

- `popup/` — интерфейс расширения для запуска плеера и команд “Открыть файл/Открыть папку”, а также отображение последнего просмотра.
- `player/` — основная страница плеера (UI, состояние, очередь, субтитры, SmartResume).
- `background/` — service worker расширения (служебные события, установка).

### 3.2. Связи между частями

- `popup` **открывает вкладку** `player/player.html` напрямую через `chrome.tabs.create(...)`.  
  Параметры передаются через query string `?mode=file` или `?mode=folder`.  
- `player` при инициализации читает параметр `mode` и запускает соответствующий диалог открытия.
- `background` используется как служебный worker и не участвует в маршрутизации команд запуска.

Примечание по модели разрешений:

- Поиск/фокусировка существующей вкладки плеера намеренно не выполняется, чтобы не требовать разрешение `tabs` (чтение URL вкладок).

### 3.3. Данные состояния (упрощённо)

Единый объект состояния плеера включает:

- очередь: массив элементов `{ file, name, parsed, history, subFile, ... }`;
- активный индекс очереди;
- параметры воспроизведения (громкость, скорость, mute);
- режим отображения (Fit/Fill/Stretch);
- состояние субтитров (включены/выключены, сдвиг);
- A‑B loop (точки A/B);
- zoom/pan;
- активная панель интерфейса (очередь/настройки).

## 5. Вызов и загрузка

Способ вызова:

- через popup расширения (кнопки “Открыть плеер/файл/папку”);
- из drop‑зоны на странице плеера (кнопки “Открыть файл/папку”);
- Drag & Drop файлов/папок на страницу плеера;
- горячие клавиши (в т.ч. команды открытия).

Точка входа:

- `player/player.html`, инициализация в `player/js/player.js` (функция `init()`).

## 6. Входные данные

- локальные видеофайлы пользователя;
- локальные файлы субтитров пользователя;
- пользовательские команды управления (кнопки UI, хоткеи, мышь).

Организация получения файлов:

- выбор через системные диалоги (`showOpenFilePicker`, `showDirectoryPicker`) при наличии поддержки;
- перетаскивание (Drag & Drop).

---

## 7. Выходные данные

- видео/аудио поток на устройство вывода (через HTML5 Video);
- локальные записи прогресса просмотра и настроек;
- локальная запись “последний просмотр” для отображения в popup.

## 8. Краткое описание основных алгоритмов

### 8.1. Формирование очереди

1) При добавлении файлов выполняется фильтрация по расширению (список поддерживаемых расширений используется как фильтр).  
2) Для каждого видео:
- вычисляется идентификатор истории (по имени и размеру файла);
- подгружается история (если существует);
- выполняется сопоставление субтитров среди выбранного набора файлов.  
3) Очередь сортируется по “смысловому разбору” имени: show → season → sortKey → натуральное имя.

### 8.2. SmartResume

- Позиция воспроизведения сохраняется локально с задержкой (автосохранение).  
- При повторном открытии того же файла:
  - если прогресс находится в допустимом диапазоне (не “почти начало” и не “почти конец”), показывается окно предложения продолжить.

### 8.3. Субтитры

- При загрузке субтитров текст читается локально.  
- Форматы SRT/ASS/SSA конвертируются в WebVTT.  
- Для сдвига тайминга применяется пересчёт временных меток VTT, после чего создаётся Blob и подключается через `<track>`.

### 8.4. Открытие папки

- Каталог выбирается пользователем.
- Выполняется рекурсивное сканирование (с ограничением глубины), собираются видео/субтитры.
- Если видео не найдено — выводится уведомление.

---

## 9. Обработка ошибок и сообщения

Программа должна:

- уведомлять пользователя о невозможности открыть файл/папку при ошибках;
- уведомлять о неподдерживаемом декодировании (ошибка воспроизведения);
- не завершаться аварийно при отмене диалогов выбора.

Конкретные тексты уведомлений могут уточняться и не являются частью интерфейсного контракта, важен факт корректной реакции.
